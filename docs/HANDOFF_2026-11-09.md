## 4. How a release works

Each release has a workspace at `../product-modern-20261107/releaseN`. Generators and
check scripts are in `../product-modern-20261107/release-tools`.

1. Commit in `source`.
2. Run the generator and build. Use `build-release26.sh` for app-only releases and
   `build-release25.sh` for one migration. Copy them for the new number, and set the
   new predecessor, commit, schema and previous artifact.
3. Run `qualify.mjs run first`.
4. Run `operator.mjs prepare`, then `check`. Both are read-only on production.
5. Run `operator.mjs approve "<owner's words>"`, then `apply`.
6. Run `operator.mjs verify` with output sent to a file. It waits for the next natural
   monitor run on a 5-minute cycle.

`apply` is single-use. **If it stops, never run it again.** Read the stop reason and
check production read-only. Rehearse money paths on the live database inside a
transaction that always rolls back.

For any migration that patches a function, list every touched function in the
operator's `ADDED` and `CHANGED` lists. Find them by comparing definitions before and
after on a native test database.

## 5. Traps that already cost time

- **Capabilities check.** `remote.py` requires `/api/payments/capabilities` to equal
  the response saved at prepare. A release that adds a field stops with
  `HEALTH_TIMEOUT_NO_RETRY` after the database commit. Update the comparison first.
- **Receipt label.** The app-only `remote.py` still writes `'schema':141` in its
  receipt. The real schema is 142. Retarget it in the next generator.
- **Caddy allowlist.** A new `/api/account/*` route returns 403 "Unavailable". Reuse an
  allowed route such as `POST /api/checkout` or a `GET` with a query. `/api/admin-orders/*`
  has no such limit.
- **Test in Daftra mode.** Earlier tests in built-in mode missed a checkout failure.
- **Compare tests with the live commit.** Many older tests already fail on it. Success
  means no test that passed now fails, not zero failures.
- **Meta tests.** Staff accounts are excluded, so test as a guest. Headless Chrome needs
  `navigator.webdriver` hidden, the automation flag off and a normal user agent.
- **Pixel flags.** `fbq.disablePushState` and `fbq.allowDuplicatePageViews` must stay set
  together. With only the first, later PageViews vanish.
- **Native tests.** Kill any orphaned `email-audit-pg` first.
- **zsh.** Lines of `=====` abort commands, and `timeout` is not installed.
